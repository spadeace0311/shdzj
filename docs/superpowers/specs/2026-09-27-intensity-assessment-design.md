# 上海市地震应急评估与辅助决策系统

## 烈度快速评估设计规格

日期：2026-09-27

状态：已确认设计，待用户审阅

所属系统：上海市地震应急评估与辅助决策系统

上游规格：

- `docs/superpowers/specs/2026-09-17-shanghai-earthquake-emergency-decision-system-design.md`
- `docs/superpowers/specs/2026-09-25-cenc-realtime-collection-lifecycle-design.md`

## 1. 建设目标

本阶段建设地震正式报触发后的快速烈度评估链路，把现有 Temporal 任务骨架接通为可执行、可验证、可追溯的模型烈度、仪器烈度和融合烈度计算。

本阶段需要解决以下问题：

- 正式速报和每次正式报更正能够自动创建独立的评估版本。
- 在上海市行政边界外扩 100 公里的 1 公里规则网格上生成连续烈度场。
- 使用有明确文献来源的上海及周边地区烈度衰减关系计算模型烈度。
- 根据震源机制、有限断层、人工覆盖或震中附近断裂确定破裂方向。
- 通过来源无关的适配器接收仪器烈度产品；正式产品未接入时明确返回不可用。
- 在仪器产品可用时进行逐格反方差融合，不可用时稳定降级为模型烈度。
- 对结果、算法、参数、数据来源、质量、失败、重试、超时和更正过程进行审计。
- 在 Z440 单机部署条件下，从正式报成功入库到完整烈度结果可查询控制在 5 分钟内。

本阶段不生成损失评估、专题图、报告或指挥大厅协同成果。本规格中的 5 分钟验收只覆盖烈度评估链路，不降低系统最终版本对 27 类图件和全部报告在 5 分钟内产出的总体验收要求。

## 2. 范围边界

### 2.1 本阶段范围

- `intensity.model`、`intensity.instrument` 和 `intensity.fusion` 三类任务的实际计算。
- 上海区域配置、网格定义、参数版本和结果版本。
- 模型烈度的长轴、短轴、方向、二维场构造、标准差和外推标记。
- 仪器烈度产品接口、状态校验、质量映射和首期 `unavailable` 行为。
- 模型与仪器烈度的反方差融合、覆盖范围回退、区间和质量分级。
- 正式报、更正报、幂等、重试、失败降级、有效版本和超时行为。
- PostgreSQL/PostGIS 元数据与栅格结果持久化。
- 受认证的结果摘要查询接口。
- 自动化测试、故障注入、性能基准和可复现验收证据。

### 2.2 明确不在本阶段范围

- 不实现人口受灾、房屋破坏、人员伤亡、经济损失或资源需求评估。
- 不实现 27 类专题图、专业版报告或成果流转。
- 不接入 EQIM、独立网段仪器烈度、现场灾情、遥感或人工上报数据。
- 不实现 AI 问答、知识库、地图联动或自动联网检索。
- 不实现指挥大厅全部工作组界面和任务协同。
- 不实现测试地震、演练、每日随机触发或手工触发。
- 不实现区级或兄弟省份的实际部署，只保留可替换区域配置。
- 不把本阶段结果描述为官方烈度或正式发布结论。

## 3. 已确认关键决策

- 总体架构保持“现有模块化单体 + Temporal 编排 + 可替换计算引擎”，不拆独立计算服务。
- 首期仅计算烈度，不启动后续损失、制图和报告任务。
- 上海区域网格范围为上海市行政边界外扩 100 公里，规则网格分辨率 1 公里。
- 连续烈度保存到 0.1 度精度，专题等值线未来按整度输出。
- 模型烈度是必需任务；仪器烈度是可选任务；融合烈度是必需任务。
- 模型烈度最终失败或融合烈度最终失败时，本次评估运行失败。
- 仪器烈度不可用或失败时，融合结果降级为 `model_only`，不得伪造仪器场。
- 正式报和每次内容变更有变化的更正报分别建立独立评估运行并完整重算。
- 5 分钟从最新有效报文成功入库时刻起算。
- 到 5 分钟仍未完成时继续计算并告警，不截断、不发布未完成结果。
- 首期公开地震事件来源只采用 CENC，不要求人工确认。
- 上海作为省级平台设计，未来通过 `RegionProfile`、参数和数据适配器支持区级和兄弟省份。

## 4. 总体架构

```text
CENC 正式报/更正报
        |
        v
生命周期 Outbox
        |
        v
Assessment Dispatcher -> Temporal Workflow
                              |
                 +------------+------------+
                 |                         |
                 v                         v
         intensity.model          intensity.instrument
                 |                         |
                 +------------+------------+
                              |
                              v
                      intensity.fusion
                              |
                              v
                   PostgreSQL / PostGIS
                运行、任务、版本和栅格结果
```

保持现有模块化单体边界：

- FastAPI 提供受认证的查询接口。
- Dispatcher 消费生命周期 Outbox 并启动稳定 Workflow。
- Temporal Workflow 只编排任务和依赖，不包含公式或空间算法。
- Temporal Activity 调用应用服务，不直接操作 GIS 栅格。
- 烈度计算模块负责确定性算法、质量校验和产物构造。
- PostgreSQL/PostGIS 是运行状态、版本元数据和栅格成果的持久化边界。

## 5. 区域配置与网格

### 5.1 RegionProfile

新增版本化 `RegionProfile`，首期至少包含：

- `region_id=shanghai`
- 区域名称和行政级别。
- 行政边界版本及几何。
- 网格外扩距离，首期为 100 公里。
- 网格分辨率，首期为 1 公里。
- 网格源点、范围、坐标参考系和网格定义版本。
- 默认模型参数集版本。
- 默认融合策略版本。
- 仪器烈度提供者配置。
- 断裂数据版本。
- 模型适用范围和质量阈值。

业务代码不得通过硬编码 `if region == "shanghai"` 选择公式。上海与未来其他区域之间的差异必须进入 `RegionProfile`、参数集或数据提供者。

### 5.2 网格定义

- 使用固定、可复现的网格定义，网格单元以稳定的 `grid_x`、`grid_y` 标识。
- 上海默认在 EPSG:32651（WGS 84 / UTM zone 51N）中生成规则 1 公里网格，网格范围由上海行政边界外扩 100 公里确定。
- 对外结果统一保存 WGS84 经纬度空间参考和原始投影元数据。
- 网格中心经纬度由网格定义推导，不在每个单元格重复保存。
- 网格定义版本至少包含源点、分辨率、行列范围、投影和计算校验和。
- 同一版本定义下重复运行必须生成完全相同的网格标识和单元格顺序。

### 5.3 距离

- 模型公式中的 `R` 是震中到网格中心的震中距，单位为公里。
- 距离使用版本化的 WGS 84 椭球大地测量逆解计算，不使用经纬度直接相减。
- 断裂距离和震中 20 公里候选范围使用同一距离定义。
- 距离方法和参数版本必须随结果保存。

## 6. 模型烈度

### 6.1 文献来源

首期采用公开上海本地烈度衰减研究：

陈婧、杨彦明、肖爽、赵文舟，《基于非线性拟合的上海及周边地区地震烈度衰减关系研究》，《高原地震》2019 年第 31 卷第 3 期。

DOI：`10.3969/j.issn.1005-586X.2019.03.002`

长轴公式：

```text
Ia = 3.4142 + 1.0353M - 0.96272 ln(Ra + 8.0209)
σa = 0.6310
```

短轴公式：

```text
Ib = 3.1626 + 1.0379M - 0.97451 ln(Rb + 7.6851)
σb = 0.6638
```

其中 `M` 使用 CENC 正式报震级，`R` 单位为公里，`ln` 为自然对数。

### 6.2 适用范围与深度

- 文献样本为 1950 至 2017 年上海及周边 26 次地震、52 条等震线。
- 主要震级范围为 `4.0 ≤ M ≤ 6.2`。
- 超出震级范围时允许计算，但结果必须保存 `model_extrapolated=true`。
- 外推结果不得用于宣称模型精度或生成正式科研结论。
- 首期不将震源深度代入公式。
- 不得使用 `sqrt(R²+h²)` 或类似方式任意制造新的深度修正模型。
- 如需深度修正，必须先取得可验证的上海本地研究和参数版本，再单独发布算法版本。

### 6.3 破裂方向优先级

破裂方向按以下顺序选择：

1. 经审核的人工覆盖方向。
2. 震源机制给出的破裂面方向。
3. 有限断层模型给出的破裂走向。
4. 震中 20 公里范围内最近断裂的推测走向。
5. 无可靠方向时使用长短轴平均，并标记方向不确定。

候选断裂距离相同时，按稳定断裂业务键排序，保证重复计算一致。

震源机制存在多个可能节面时，只有具备明确选面规则的结果才能作为破裂方向；不得把任意节面走向冒充最终破裂方向。

无可靠方向时，格点烈度直接取同一震中距下长轴和短轴结果的平均值：

```text
I(no_direction, R) = (Ia(R) + Ib(R)) / 2
σ(no_direction) = sqrt((σa² + σb²) / 2)
```

同时保存 `direction_status=uncertain`。

### 6.4 二维模型场构造

论文给出的是一维长轴和短轴衰减公式。首期采用经确认的“强度相关椭圆轴比等价距离法”构造二维场，版本标识为 `axis-ratio-v1`。

给定候选烈度 `I`，分别由长轴和短轴公式反求同一烈度对应的半径 `Ra(I)` 和 `Rb(I)`。设破裂走向为长轴方向，格点方位与长轴夹角为 `Δ`：

```text
x = R * cos(Δ)
y = R * sin(Δ)
```

构造等价距离：

```text
Re(I) = sqrt(x² + (Ra(I) / Rb(I) * y)²)
```

格点烈度满足：

```text
I = Ia(Re(I))
```

首版使用单调二分求解：

- 搜索区间为 `-20.0` 至 `12.0` 度。
- 绝对容差为 `1e-6` 度。
- 最大迭代次数为 64。
- 终止要求为区间宽度不大于容差，或函数值绝对值不大于容差。

- 长轴方向上严格还原 `Ia(R)`。
- 短轴方向上严格还原 `Ib(R)`。
- 中间方向通过强度相关椭圆轴比连续过渡。
- 收敛失败必须使模型任务失败，不得回退到未经版本化的近似公式。
- 标准差场按方向投影权重组合：

```text
wa = cos²(Δ)
wb = sin²(Δ)
σ = sqrt(wa * σa² + wb * σb²)
```

长轴和短轴方向分别严格还原 `σa` 和 `σb`。

`axis-ratio-v1` 是二维场工程构造方法，不宣称是原论文直接给出的二维算法。

### 6.5 数值与输出

- 所有中间计算使用双精度浮点。
- 连续烈度值、标准差和区间保存原始计算结果。
- 对外展示连续烈度时四舍五入到 0.1 度。
- 未来等值线生成使用整度分级。
- 每个格点保存烈度、标准差、模型权重和方向元数据。
- 结果保存震级、震中、距离公式版本、方向来源、方向角、断裂版本和外推标记。

### 6.6 旧系统公式

旧系统的长轴公式只允许用于兼容性诊断，不作为本规格的正式算法来源。

旧系统短轴参数不完整，禁止宣称当前实现复现旧系统官方模型，也禁止用旧系统输出反向校准本模型。

## 7. 仪器烈度

首期没有正式、可验证且可接入的仪器烈度网格，因此默认适配器必须明确返回 `unavailable`。

不得从 CENC 或 Wolfx 事件报文中的单点 `intensity` 字段伪造仪器烈度场。单点值只可作为审计或参考信息保存，不参与融合。

### 7.1 支持的产品形态

适配器接口预留两种产品：

- `GRID`：来源系统已经生成的烈度网格。
- `STATION`：台站观测或台站估算值。

原始 `STATION` 点值不得直接进入逐格融合。必须先由具有明确方法和版本的仪器产品生成器转换为网格产品。首期不实现台站插值算法。

### 7.2 产品元数据

仪器产品至少包含：

- 来源系统和提供者。
- 产品编号和产品版本。
- 观测时间和产品生成时间。
- 空间参考系、空间范围和分辨率。
- 网格或台站标识。
- 原始值、标准差或误差信息。
- 质量等级和来源质量代码。
- 原始数据校验和和标准化后校验和。

### 7.3 状态与质量

产品状态：

- `available`
- `partial`
- `unavailable`
- `invalid`
- `stale`

质量等级：

- `Q1`
- `Q2`
- `Q3`
- `Q0`

首版默认权重：

- `Q1 = 1.0`
- `Q2 = 0.5`
- `Q3 = 0.25`
- `Q0 = 0`

具体阈值必须进入版本化融合策略，不得散落在适配器代码中。

## 8. 融合烈度

### 8.1 反方差融合

仪器产品可用时，对存在有效仪器值的格点逐格计算：

```text
wm = qm / (σm² + ε)
wi = qi / (σi² + ε)

If = (wm * Im + wi * Ii) / (wm + wi)
σf = sqrt(1 / (wm + wi))
```

其中：

- `Im` 是模型烈度。
- `Ii` 是仪器烈度。
- `σm` 是模型标准差。
- `σi` 是仪器标准差。
- `qm` 和 `qi` 是版本化质量权重。
- `ε` 是防止除零的版本化小量。

当有效仪器权重为零、产品不可用、产品无效或在覆盖范围外时，融合值等于模型值，并标记 `fusion_mode=model_only`。

### 8.2 区间

首版使用正态近似：

```text
P10 = If - 1.2816 * σf
P90 = If + 1.2816 * σf
```

区间按融合策略版本可替换。任何替换都必须产生新的算法或参数版本，不能改变历史结果。

### 8.3 融合质量

建议首版质量分级：

- `F1`：有效仪器覆盖率大于等于 90%，且覆盖区面积加权 95 分位融合标准差小于等于 0.75 度。
- `F2`：有效仪器覆盖率大于等于 50%，且覆盖区面积加权 95 分位融合标准差小于等于 1.25 度。
- `F3`：有完整模型烈度，但未达到 `F1` 或 `F2`。
- `F0`：没有可用融合烈度。

覆盖率的分母是本区域版本中的全部有效网格单元，分子是存在有效仪器值且 `qi > 0` 的网格单元。

没有仪器产品时，首期统一记录：

```text
instrument_status = unavailable
fusion_mode = model_only
fusion_quality = F3
```

### 8.4 每个格点保存

融合栅格至少保存：

- 融合中心值。
- 融合标准差。
- `P10` 和 `P90`。
- 模型权重。
- 仪器权重。
- 质量代码。
- 模型值。
- 仪器值及其存在状态。
- 模型参数版本、仪器产品版本和融合策略版本。

没有融合烈度时，不得生成伪造损失结果。

## 9. 运行、任务、更正报与超时

### 9.1 运行版本

每次正式报或更正报对应一条独立 `assessment_run`，历史版本不可覆盖。运行记录增加：

- `report_ingested_at`
- `deadline_basis_at`
- `deadline_exceeded_at`
- `completed_at`
- `duration_ms`
- `algorithm_bundle_version`
- `superseded_by_run_id`
- `superseded_at`

`deadline_basis_at` 使用最新有效报文成功入库时刻。首份正式报的 `T1` 保持不变；后续更正报不重置 `T1`，但使用自己的 `report_ingested_at` 计算本版本 5 分钟验收时限。

### 9.2 状态

运行状态：

```text
pending -> running -> completed / failed / canceled
```

任务状态：

```text
pending -> running -> succeeded / failed / skipped / canceled
```

更正报到来后，旧运行通过 `superseded_by_run_id` 和 `superseded_at` 标记。已完成的旧结果保持不可变；未完成的旧运行尽量取消并保留部分审计信息。

仪器产品不可用是任务成功并返回 `unavailable`，不是执行失败。仪器链路发生临时故障且重试耗尽时，任务可以失败，但运行仍可在模型和融合完整时成功。

### 9.3 最新版本与回退成果

- `latest_assessment_run_id` 指向该事件最新的正式报或更正报运行，无论成功、失败或仍在计算。
- `effective_assessment_run_id` 指向最近一次 `completed` 且产物完整的运行。
- 最新更正报尚在计算或计算失败时，`effective_assessment_run_id` 可以继续指向旧修订，但 API 必须返回 `is_latest_revision=false` 和 `is_fallback=true`。
- 不得把新修订参数、时间或震级与上一版烈度栅格混合展示。
- 新版本完成后，在同一事务中更新 `effective_assessment_run_id` 和版本审计。

### 9.4 幂等

- Workflow ID 由 Outbox 标识稳定派生。
- 计算幂等键为 `(run_id, task_key, algorithm_version, input_fingerprint)`。
- `input_fingerprint` 是对标准化事件修订、区域配置、网格、参数集和上游仪器产品标识进行稳定序列化后计算的 SHA-256。
- 同一 Outbox 重复投递只能产生一条运行。
- 同一任务重复执行只能产生一个逻辑产物。
- Worker 崩溃恢复后可以继续未完成运行，不得重复发布版本。

### 9.5 重试

只对可恢复的基础设施、网络、数据库或外部读取错误重试：

- 最多尝试 3 次。
- 两次重试的基准退避为 2 秒和 8 秒。
- 每次退避乘以 `0.8` 至 `1.2` 的随机系数，避免同时重试。

以下确定性错误不重试：

- 输入字段缺失或非法。
- 坐标、震级或距离越界且没有明确外推策略。
- `axis-ratio-v1` 不收敛。
- 参数版本缺失或校验失败。
- 输出校验失败。

### 9.6 超时

- 5 分钟从最新有效报文成功入库时刻起算。
- `60 秒 / 60 秒 / 90 秒`是模型、仪器和融合任务的阶段告警线。
- 到达阶段告警线不强制杀死任务。
- 到达 5 分钟仍未完成时，设置 `deadline_exceeded_at` 并告警，但继续完成有效计算。
- 后续成功时正常发布，并永久保留超时记录。
- 技术安全熔断固定为 30 分钟，配置名为 `ASSESSMENT_WORKFLOW_SAFETY_TIMEOUT_SECONDS=1800`。
- 30 分钟独立于 5 分钟业务验收口径，只用于防止永久挂起；达到 30 分钟仍未完成时运行失败并告警，不发布不完整结果。

## 10. 数据模型

### 10.1 现有表扩展

`assessment_runs`：

- 保持每次修订一条运行及唯一约束。
- 增加第 9.1 节所列版本、时限和 supersede 字段。
- 首期运行截止时间改为 `deadline_basis_at + 300 秒`。

`assessment_tasks`：

- 保持 `(run_id, task_key)` 唯一。
- 增加 `input_fingerprint`、`output_checksum`、`algorithm_version` 和结构化进度状态。
- 保留 `attempt_count`、`max_attempts`、`result` 和 `last_error`。

`earthquake_events`：

- 增加 `latest_assessment_run_id`，指向最新修订运行。
- 增加 `effective_assessment_run_id`，指向最近一次完整成功的运行；该运行可以来自较早修订并作为回退成果。

### 10.2 任务尝试审计

新增任务尝试记录，保存：

- 任务和尝试次数。
- 开始、结束时间。
- 临时或最终状态。
- 错误分类和脱敏错误摘要。
- 输入指纹和输出校验和。

同一任务最多保留配置规定的尝试记录数量，正式运行和最终结果不受清理策略影响。

### 10.3 烈度产物

新增 `intensity_field_products`，按运行和产品类型保存：

- `model`
- `instrument`
- `fusion`

每个产品至少保存：

- 运行 ID、任务 ID 和产品类型。
- 算法版本、参数版本和融合策略版本。
- 网格定义版本和区域配置版本。
- 输入数据摘要、原始校验和和输出校验和。
- 状态、质量等级、覆盖率、空间范围。
- 最小值、最大值、均值和分位统计。
- 来源产品编号和观测时间。
- 创建、完成和发布时间。

### 10.4 栅格存储

首版使用 PostgreSQL/PostGIS 保存同一产品定义下的多波段栅格，不把每个网格单元存为一行，也不把大型结果放入 JSONB。

波段定义由产品类型确定：

- 中心烈度。
- 标准差。
- `P10`。
- `P90`。
- 模型权重。
- 仪器权重。
- 质量代码。
- 模型值。
- 仪器值及存在状态。

波段元数据保存波段号、类型、单位、无数据值、缩放方式和校验和。

若以后引入外部对象存储，只替换 `IntensityArtifactStore` 实现，不改变领域契约和历史追溯字段。

## 11. 代码结构

```text
backend/app/intensity/
  domain.py
  grid.py
  parameters.py
  model.py
  instrument.py
  fusion.py
  service.py
  repository.py
  models.py
  schemas.py
```

职责：

- `domain.py`：纯领域对象、枚举、错误分类和结果契约。
- `grid.py`：区域网格定义、稳定格点标识和距离入口。
- `parameters.py`：版本化参数加载、校验和摘要。
- `model.py`：长轴、短轴、方向解析和 `axis-ratio-v1` 二维场。
- `instrument.py`：仪器产品协议、状态校验和适配器注册。
- `fusion.py`：反方差融合、质量权重、区间和融合分级。
- `service.py`：加载输入、调用纯算法、校验结果和保存事务。
- `repository.py`：数据库和栅格持久化。
- `models.py`：SQLAlchemy 模型。
- `schemas.py`：API 和内部序列化契约。

约束：

- `domain.py`、`grid.py`、`model.py`、`instrument.py` 和 `fusion.py` 不导入 FastAPI、Temporal、SQLAlchemy 或 PostGIS 类型。
- Temporal Activity 只调用 `IntensityService`。
- API 路由不直接拼装算法或查询栅格波段。
- 损失评估、地图、报告和问答只能消费 `FusionProduct` 的已发布版本。

## 12. 参数与版本

公式结构放入代码，数值参数和策略放入版本化参数集。

模型参数集至少包含：

- 文献引用。
- 长轴和短轴系数。
- 标准差。
- 适用震级范围。
- `axis-ratio-v1` 容差、最大迭代次数和方向标准差权重。

融合策略至少包含：

- `Q1/Q2/Q3/Q0` 权重。
- `ε`。
- `F1/F2/F3/F0` 阈值。
- `P10/P90` 分位系数。

每个参数集保存：

- 参数集标识和版本。
- 来源和校验和。
- 发布状态和生效时间。
- 变更说明。

运行记录保存参数集版本，不复制并覆盖历史参数。未来数据管理平台可以发布新版本，但不能修改历史运行引用的参数内容。

## 13. 接口

保留现有运行和任务状态接口，并增加烈度结果摘要。

现有：

```text
GET /api/v1/assessments/events/{event_id}/current
```

该接口返回最新运行状态，并同时返回当前回退成果的摘要。增加：

```text
GET /api/v1/assessments/runs/{run_id}/intensity
```

返回内容至少包括：

- 运行、事件和修订标识。
- 模型、仪器和融合产品状态。
- 算法、参数、网格和区域版本。
- 覆盖率、质量和统计摘要。
- 是否外推、方向来源和方向角。
- 是否超时、是否当前有效和是否被 supersede。
- 产物校验和和生成时间。
- `is_latest_revision`、`is_fallback` 和实际采用的修订标识。
- 可供后续地图和报告模块引用的内部栅格产物标识。

权限沿用现有评估读取角色：超级管理员、组长、副组长、组员和查看者。

## 14. 异常处理与降级

- 模型输入非法：任务失败，运行失败，不生成融合结果。
- `axis-ratio-v1` 不收敛：任务失败，记录迭代状态，不降级到未验证公式。
- 仪器产品不可用：任务成功，融合使用 `model_only`。
- 仪器产品格式无效：记录无效原因，融合使用 `model_only`。
- 仪器产品过期：默认不参与融合，融合使用 `model_only`。
- 数据库临时不可用：任务按可恢复错误重试。
- 栅格写入失败：不得把产品标记为完成。
- 产品校验和失败：不得更新有效运行指针。
- 更正报到达：新版本优先，旧版本保留审计。
- 旧版本任务恢复：不得覆盖新版本有效指针。

所有错误摘要必须脱敏，不包含凭据、认证报文或敏感连接信息。

## 15. 测试设计

### 15.1 模型单元测试

- 已知震级和距离下，长轴、短轴和标准差数值正确。
- 连续计算使用双精度，对外格式化为 0.1 度。
- 距离增大时烈度单调不增。
- 震级增大时烈度单调不减。
- 短轴结果不高于同距离长轴结果。
- 所有输出为有限值，不出现 `NaN` 或无穷值。
- `M < 4.0` 或 `M > 6.2` 时稳定标记外推。

### 15.2 二维场测试

- 长轴方向严格等于长轴公式。
- 短轴方向严格等于短轴公式。
- 方向相反的两侧在无其他偏心参数时对称。
- 方向角旋转后，场应随之旋转。
- `axis-ratio-v1` 在固定容差内收敛。
- 不收敛输入必须失败，不得静默近似。
- 无破裂方向时使用长短轴平均并标记方向不确定。

### 15.3 方向优先级测试

- 人工覆盖优先于所有自动来源。
- 震源机制优先于有限断层和断裂候选。
- 有限断层优先于断裂候选。
- 20 公里内候选断裂按距离及稳定业务键选择。
- 20 公里外断裂不用于方向推断。

### 15.4 仪器适配器测试

- 首期默认返回 `unavailable`。
- `available`、`partial`、`invalid`、`stale` 状态分类正确。
- 单点事件烈度字段不进入融合。
- `STATION` 原始点值未经网格化时不得直接融合。
- 产品质量和来源元数据完整保留。

### 15.5 融合测试

- 反方差权重公式正确。
- `Q1/Q2/Q3/Q0` 权重映射正确。
- 仪器范围外严格回退模型值。
- 仪器不可用、无效或过期时生成 `model_only`。
- `P10 <= If <= P90`。
- 模型与仪器值相等时融合中心值保持不变。
- 输入顺序变化不改变结果。
- 质量等级 `F1/F2/F3/F0` 边界正确。

### 15.6 幂等和并发测试

- 重复 Outbox 只产生一条运行。
- 同一任务重复执行不产生多个逻辑产物。
- Worker 在模型完成后、融合发布前崩溃并恢复。
- 两个并发 Worker 不重复发布同一版本。
- 更正报与旧运行并发时，旧结果不会覆盖新版本。

### 15.7 更正报和失败测试

- 旧任务运行中收到更正报。
- 旧任务已完成时收到更正报。
- 新更正报模型失败或融合失败。
- 乱序旧报再次到达。
- 仪器任务失败但模型和融合成功。
- 数据库短暂不可用后恢复。
- 栅格写入中断后不出现已完成空产物。

### 15.8 时间测试

- 使用带时区的 `T1`、报文入库时刻和 UTC 单调时钟。
- `deadline_basis_at + 5 分钟`计算正确。
- 5 分钟到达未完成时只标记超时并告警。
- 超时后完成仍可发布，超时历史不丢失。
- 更正报使用自身入库时刻计算超时。

### 15.9 性能和端到端测试

在 Z440、1 公里网格和固定基准区域配置上执行：

- 模型和仪器任务可并行。
- 单任务目标为 `60/60/90` 秒。
- 从正式报成功入库到完整融合产物可查询不超过 5 分钟。
- 重复运行的输出校验和一致。
- 从 Outbox 到 API 能读取运行、任务、版本、质量和统计摘要。

## 16. 验收标准

- 正式报成功入库后自动创建并执行烈度评估运行。
- 每次更正报创建独立运行和版本，旧结果不可覆盖。
- 模型烈度公式、参数、外推范围、方向和二维场构造可追溯。
- 模型烈度是必需产物，最终失败时运行失败。
- 仪器产品缺失时不伪造数据，融合稳定回退 `model_only`。
- 仪器产品可用时逐格反方差融合并输出质量分级。
- 每个格点包含中心值、标准差、`P10`、`P90`、权重和质量信息。
- 只有完整成功的融合产物可以成为当前有效成果。
- 重复投递、重试和 Worker 恢复不产生重复发布。
- 5 分钟超时会告警但不会发布不完整结果。
- 结果接口能够读取版本、状态、质量、统计和校验和。
- Z440 上烈度链路在 5 分钟内完成并可查询。
- 后端测试、Ruff、迁移、真实 PostgreSQL/PostGIS 集成测试和性能验证全部通过。
- 日志、接口和文档不泄露任何凭据。
