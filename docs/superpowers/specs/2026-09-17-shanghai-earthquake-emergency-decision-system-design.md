# 上海市地震应急评估与辅助决策系统设计规格

日期：2026-09-17  
状态：需求与技术路线已确认，待用户审阅  
当前阶段：设计规格，不进入编码、脚手架、部署实施

## 1. 建设目标

建设面向上海市地震局震后应急处置的省级地震应急评估与辅助决策平台。平台在正式速报入库后自动启动评估流程，在规定时限内生成灾害评估成果、专业图件、报告和任务清单，支撑局领导判断制度响应等级，并支撑地震应急指挥大厅内各工作组协同、成果流转和大屏展示。

平台同时承担以下长期目标：

- 当前服务上海市地震局本级，覆盖上海市行政区域及边界海域。
- 未来能够将能力扩展到区政府，不改变核心事件、评估、制图和任务模型。
- 未来可将区域边界、组织、数据、模板、模型参数、数据来源和通知渠道配置化后，用于兄弟省份地震局独立部署。
- 当前采用单机部署，不实现多租户；设计保留组织隔离和服务拆分能力。

## 2. 范围边界

### 2.1 首期范围

- 接入自动速报、正式速报、正式报修正和人工触发事件。
- 自动建议上海市制度响应等级，并独立展示中国地震局应急服务响应等级。
- 自动生成模型烈度、仪器烈度、融合烈度以及灾害损失快速评估结果。
- 自动生成 27 类专业图件、4 类核心文档或演示稿、8 类背景文档。
- 支持 7 个工作组任务协同、时限提醒、成果上传、确认、版本流转和大屏展示。
- 支持数据管理、校验、版本发布、回滚、更新提醒和事件快照。
- 支持 AI 文字问答、知识库检索、确定性空间计算和地图联动。
- 支持每日随机测试、手工测试及演练事件。
- 支持超级管理员运维、成果覆盖、成果删除、原始报文删除和日志删除。

### 2.2 明确不在首期范围

- 不接入内网 EQIM。
- 不接入当前独立网段中的仪器烈度系统，首期采用公开数据接口和模型结果进行替代和融合。
- 不负责余震目录和地震台站原始观测业务，相关图层由外部权威数据补齐或由责任组提供。
- 不在首期接入现场灾情、遥感灾害解译等震后现场数据。
- 不开发手机端。
- 不自动替代现有公文、传真、电话等对外报送渠道。
- 不自动启动制度响应，不替代领导决策和发布命令。
- 不提供完整的在线 GIS 绘制和编辑能力，数据管理首期以导入、校验、版本发布为主。
- 不输出 PDF，图件输出为 JPG 或 PNG，文档输出为 DOCX，演示稿输出为 PPTX。

## 3. 已确认的关键决策

- `T0` 为发震时刻。
- `T1` 为首次正式速报入库时刻。
- 自动速报只建立待定事件和震情记录，不启动损失评估。
- 正式速报到达后由平台自动启动评估和任务流程，并给出制度响应建议。
- 平台响应是自动化业务流程，制度响应仍由局领导决定。
- 平台响应等级建议和中国地震局应急服务响应等级分开计算、分开展示。
- 自动评估范围包括上海市行政区域及边界海域、外省波及上海、距本市边界 20 公里以内以及预测烈度达到 2 度以上的事件。
- 其他地震只记录和通知，不建立完整评估任务。默认自动评估烈度阈值为 2 度，并允许在设置中调整。
- 真实事件优先；真实事件发生时，测试任务暂停，演练任务按配置暂停或终止。
- CENC 是首期唯一采用的公开地震信息来源，不需要人工确认后才进入系统。
- CENC 未发布但上海地震台网正式测定的地震，可由授权用户手工启动完整评估。
- 所有事件、模型、基础数据、模板、参数和知识库在事件启动时锁定快照，重算生成新版本。
- 自动首版成果只供内部使用，不由平台自动外报。
- 旧系统只作为业务流程、交互、成果种类和数值合理性参照，不作为数值复现验收条件。
- 模型、参数、易损性矩阵和价格体系全部重建为可配置、带版本、可追溯来源的模型。
- 首期采用高德地图为主、天地图备用；正式出图使用本地底图和本地缓存服务。

## 4. 用户与权限

### 4.1 用户类型

- 局领导和管理者：查看事件态势、响应建议、评估成果、任务进度和辅助决策材料。
- 工作组组长：管理本组任务、确认和发布本组成果。
- 代理副组长：组长不在时，按名单顺序代理组长权限。
- 普通组员：接收任务、上传过程和成果、查看授权范围内信息。
- 数据管理人员：导入、校验、维护和提交数据候选版本。
- 数据复核和发布人员：审核数据质量、发布和回滚数据版本。
- 超级管理员：拥有完全权限，可覆盖错误成果、直接重新发布、彻底删除原始报文、已发布报告和操作日志。
- 只读用户：查看授权事件、成果和大屏内容。

### 4.2 权限规则

- 任务默认分派到工作组，不自动指定个人。
- 组长存在时由组长承担确认和发布权限。
- 组长不在时，由显式设置的代理副组长按预案名单顺序承担职责。
- 平台不启用二次验证。
- 高风险操作不要求再次输入密码，不强制填写操作原因。
- 所有可保留的操作仍记录操作人、时间、对象和结果；超级管理员按已确认要求可以删除日志。

## 5. 事件主流程与时限

### 5.1 主时钟

| 时刻 | 系统动作 |
| --- | --- |
| `T0` | 发震时刻。自动速报到达后建立待定事件和震情记录。 |
| `T0+3分钟以内` | 自动速报应到达并显示震中、震级、深度和初步影响范围，不开展损失评估。 |
| `T0+5分钟以内` | 正式速报应到达，并以首次正式速报入库时刻作为 `T1`。 |
| `T1` | 首次正式速报入库，触发评估、任务建立、响应建议、快照锁定和正式出图。 |
| `T1+5分钟以内` | 必须完成全部 27 类图件、4 类核心文档或演示稿、8 类背景文档。 |
| `T0+30分钟` | 应急技术组进入大厅并运行系统；完成预案规定的快速评估简报等任务。 |
| `T0+30至60分钟` | 完成《地震灾害快速评估专报》及相关工作组阶段成果。 |
| `T0+60分钟以后` | 持续产出专业图件、文字说明和动态更新成果。 |

预案任务按 `T0` 计时，自动评估和自动成果按 `T1` 计时。`T1+5分钟` 是首期硬验收线，从正式速报入库开始，到最后一份图件或文档写入成果存储为止。

### 5.2 正式报修正

- 首次正式速报入库时刻固定为 `T1`，后续修正不重置原始 `T1`。
- 每次正式报修正自动生成修订版评估任务，从修正报文入库起重新计算，并在 5 分钟内完成新版成果。
- 修正涉及震中位置、震级或深度时，烈度、损失、伤亡和资源需求结果全部重算。
- 新旧版本同时保留，大屏默认显示最新有效版本，并提供差异对比和修订说明。
- 修正前已完成的预案任务不撤销，受影响成果标记为已更新。

### 5.3 响应升级与降级

- 响应升级时自动追加新任务，不删除已经产生的成果和过程记录。
- 响应降级时未开始任务标记为“不再需要”，正在进行和已完成任务保留。
- 每次等级变更记录建议依据、操作人、时间和关联报文版本。

## 6. 响应等级规则

### 6.1 上海市制度响应建议

| 事件条件 | 建议等级 |
| --- | --- |
| 上海行政区域含边界 50 公里海域发生 3.0 至 3.9 级 | 一般响应 |
| 上海行政区域含边界 50 公里海域发生 4.0 至 4.9 级 | 较大响应 |
| 上海行政区域含边界 50 公里海域发生 5.0 至 5.9 级 | 重大响应 |
| 上海行政区域含边界 50 公里海域发生 6.0 级及以上 | 特别重大响应 |
| 外省波及上海且无直接死亡 | 一般响应 |
| 外省波及上海且死亡少于 10 人 | 较大响应 |
| 外省波及上海且死亡 10 人至不足 100 人 | 重大响应 |
| 外省波及上海且死亡 100 人及以上 | 特别重大响应 |

- 震源深度大于 60 公里时，制度响应建议降低一级。
- 外省震中距上海边界 20 至 100 公里时，制度响应建议降低一级。
- 平台显示建议等级、触发原因、震级或死亡人数、降级条件和数据来源。
- 预测烈度达到 2 度但仍未达到正式响应条件时，可以建立专项评估，不建议启动制度响应。

### 6.2 中国地震局应急服务响应

上海属于“长江流域大城市”，且属于人口密集地区。服务响应等级独立计算和展示：

| 震级条件 | 服务响应等级 |
| --- | --- |
| `M >= 6.0` | 一级 |
| `5.0 <= M < 6.0` | 二级 |
| `4.0 <= M < 5.0` | 三级 |
| `3.0 <= M < 4.0` | 四级 |

执行上级文件中的降级规则时，中深源按文件规定的 `/ > 70 km` 条件处理，不覆盖上海市预案规定的 `/ > 60 km` 条件。两个等级字段、计算规则和结果显示相互独立。

## 7. 数据来源与数据管理

### 7.1 当前数据基础

首期基础数据来源为 `D:\地震应急辅助决策系统\基础数据\上海应急基础数据2022.mdb` 及相关栅格数据。

已确认的主要数据包括：

- 市级建筑、人口和 GDP。
- 17 个区县和 212 个乡镇的建筑与人口数据。
- 区县经济数据。
- 1828 条断层记录和 23 条活动断层记录。
- 6141 条及 4393 条历史地震记录。
- 危险源、学校、医院、重点目标、桥梁、铁路、机场、港口、水道、隧道和油气管线等数据。

主要缺口包括：

- 高层建筑面积基本为空。
- 建筑重置单价和室内财产单价大面积为空。
- 缺少独立的地铁、疏散场地、救援队伍、文物保护单位和建筑公里格网数据。
- 所谓 `INSTRUMENT_CATALOG` 不是台站目录。
- 现有人口以行政区人口为主，不是 1 公里人口格网。
- 水库和地震动峰值加速度区划数据当前为空。

### 7.2 数据治理规则

- 数据必须可追溯，记录来源、许可、坐标系统、时间、责任单位、更新频率和质量等级。
- 公开或开源数据先补齐并标记“待复核”。
- 正式数据到位后生成新版本替换，不覆盖历史版本。
- 无可靠来源的数据不伪造数值，生成带缺数说明的图件。
- 数据更新先生成候选版本，不影响正在运行的事件。
- 事件启动时锁定基础数据、模型参数、模板和知识库快照。
- 数据更新前进行影响分析，展示受影响的模型、图件、报告和大屏图层。
- 更新时检查坐标系、几何、重复记录、空值、字段类型、空间范围、编码和模型必需字段。
- 数据流转顺序为上传、校验、预览、候选版本、复核、发布、回滚和历史留档。

### 7.3 数据管理模块

数据管理是一级模块，首期包括：

- 数据目录和元数据维护。
- Shapefile、GeoJSON、GeoPackage、CSV、XLSX 和 GeoTIFF 导入。
- 现有 MDB 的一次性迁移工具。
- 数据质量校验和错误报告。
- 候选版本、版本对比、差异查看、发布和回滚。
- 数据更新提醒和责任人配置。
- 事件快照和数据血缘。
- 操作审计和超级管理员强制覆盖。

## 10. 灾害评估模型

### 10.1 烈度

系统保留三套烈度结果：

- 模型烈度场。
- CENC 仪器烈度场。
- 融合烈度场。

融合考虑测站密度、台站到目标点的距离和观测质量。没有仪器烈度覆盖的区域使用模型烈度。仪器烈度产品不可用时，系统仍生成模型烈度，并将融合结果标记为降级质量。

### 10.2 损失评估

在融合烈度场基础上叠加人口、房屋建筑、重点目标、交通、生命线、GDP 等数据，计算：

- 建筑破坏。
- 人员死亡。
- 人员受伤。
- 人员压埋。
- 经济损失。
- 救援力量、医疗、防疫、帐篷、饮水、厕所、衣物、棉被、食品、毛毯、担架和病床等资源需求。

所有结果必须包含中心值、区间、数据质量等级、模型版本、参数版本和数据版本。

### 10.3 初始模型框架

旧系统源码提供了以下可借鉴结构：

- 建筑破坏按高层、钢筋混凝土、砌体、单层和其他五类建筑面积，乘烈度易损性矩阵和破坏状态比例。
- 死亡默认实现采用 `deathRate = a * exp(b * (I + c)) * (collapseArea / totalArea)` 结构。
- 受伤按死亡人数乘烈度相关比例计算。
- 安置按人口乘烈度相关比例计算。
- 压埋按五类建筑破坏面积乘系数并除以城市类型系数计算。
- 经济损失采用 `建筑面积 * 易损性比例 * 损失比 * 重置单价 + 室内财产损失` 结构。
- 影响场采用长轴和短轴衰减公式结构。

旧系统安装包中的实际易损性矩阵、模型系数、价格和财产参数没有完整随源码提供，因此新系统不承诺复现旧系统结果数值。新系统按旧系统结构、现行标准、上海本地修正和公开论文重建可配置模型。

模型依据至少包括：

- `GB/T 17742-2020` 中国地震烈度表。
- `GB/T 18208.4-2011` 地震现场工作第 4 部分：灾害直接损失评估。
- 上海市相关防灾和地震应急规范。
- 中国地震局应急服务响应和预案文件。
- 公开快速评估、ShakeMap、PAGER 和损失评估研究。

### 10.4 模型质量

- 核心输入缺失时，不生成虚假数值。
- 非核心图层缺少数据时，可以出图，但必须标记“待复核”。
- 每个结果可以追溯到计算过程、输入版本、模型版本和参数版本。
- 模型参数支持本地校准和版本管理。
- 开源模型和代码只用于方法借鉴或离线校核，不将不兼容许可证的组件嵌入核心平台。

## 11. 任务协同

### 11.1 工作组

平台纳入 7 个工作组：

- 新闻信息值守组。
- 监测预报组。
- 综合协调组。
- 震害评估组。
- 应急技术组。
- 后勤保障组。
- 中心站组。

现场工作队不单列为第八个组，由相关工作组抽调。纪检监督组不进入平台成果流转。

### 11.2 任务来源

- 地震预案任务。
- 正式速报触发的自动评估任务。
- 领导或综合协调组下达的临时任务。
- 数据复核和成果修正任务。
- 测试和演练任务。

### 11.3 任务规则

- 任务分派到组，不自动到个人。
- 任务记录时限、来源、责任组、优先级、状态、附件和成果。
- 组长或代理副组长确认后成果进入已发布状态。
- 系统自动成果直接显示为系统自动版。
- 修正成果生成新版本，原成果继续保留。
- 任务支持待接收、处理中、待确认、已完成、超时、不再需要和失败状态。

### 11.4 预案时限

- 震后 30 分钟：应急技术组开启大厅和系统，产出快速评估简报。
- 震后 30 至 60 分钟：应急技术组产出《地震灾害快速评估专报》。
- 震后 1 小时以后：持续产出专业图件和文字说明。
- 监测预报组 30 分钟内提供震中、历史地震和仪器烈度相关内容，1 至 2 小时提供台站、震源机制和余震目录等成果。
- 震害评估组 30 分钟内准备出队，30 至 60 分钟提供构造、断层、设防能力资料并开展现场工作。
- 中心站组按预案和平台模板承接日常与震时成果流转。

## 12. 系统模块

平台采用模块化单体、异步任务编排和并行工作进程的组合方式。首期不拆微服务，模块之间通过明确接口通信。

一级模块为：

1. 统一身份与授权。
2. 地震事件中心。
3. 数据资产中心。
4. 灾害评估中心。
5. 专业制图中心。
6. 报告生产中心。
7. 应急任务协同。
8. 指挥大厅。
9. 知识与问答。
10. 运维与演练。
11. 通知适配。

## 13. 数据流

1. 自动速报、正式速报或人工事件进入事件中心。
2. 事件中心完成去重、合并、修正和快照。
3. 规则引擎计算平台响应建议和中国地震局服务响应等级。
4. 任务编排器按事件类型和等级生成工作组任务。
5. 数据资产中心提供已发布且被事件锁定的数据版本。
6. 灾害评估中心并行计算烈度和损失。
7. 制图中心并行生成 27 类图件。
8. 报告生产中心并行生成核心文档和背景文档。
9. 成果进入版本库、任务中心和大屏。
10. AI 问答通过受控工具读取事件、数据和成果，并驱动地图联动。
11. 所有过程记录进入监控、审计和备份体系。

## 14. 技术架构

### 14.1 首期技术栈

- 前端：React、TypeScript、Vite、MapLibre GL JS、ECharts。
- 后端：FastAPI。
- 数据库：PostgreSQL、PostGIS、pgvector。
- 工作流编排：Temporal。
- 对象存储：SeaweedFS。
- 空间服务：Martin、PMTiles 或 MBTiles。
- 制图：Playwright 驱动无界面 Chromium。
- 文档：python-docx、python-pptx、Matplotlib。
- 监控：Prometheus、Grafana、Loki。
- 部署：Docker Compose。
- AI：外网阶段适配在线模型，内网阶段可切换 Ollama。

### 14.2 事件接口

- 首期地震信息来源为 CENC，采用公开接口适配层。
- 使用现有 Kanameishi `appId` 作为初期接口方式，后续再重新申请。
- 外部 API 凭据通过环境变量或受控密钥文件注入，不写入设计文档和源码。
- 自动速报、正式速报、修正报文和人工事件使用统一内部事件模型。
- 事件去重和合并使用来源、事件标识、发震时刻和震中空间关系。

### 14.3 快照和版本

事件启动时固定以下版本：

- 事件和报文。
- 烈度输入。
- 基础数据。
- 模型和参数。
- 图件模板。
- 文档模板。
- 知识库。

重算创建新评估版本，不修改原始快照。

### 14.4 性能设计

- 正式速报触发后的 27 类图件和 12 类文档并行生成。
- 底图、字体、模板、常用空间索引、浏览器进程和模型依赖预热。
- 地图和文档渲染使用本地资源，不在运行过程中依赖互联网。
- 真实事件优先调度，测试和演练任务使用较低优先级。
- 单个任务失败不阻塞其他任务。

## 15. 指挥大厅和界面

- 首期只支持桌面和大屏，不开发手机端。
- 指挥大厅整屏分辨率为 `7680 x 2430`，显示面积约 `29.16` 平方米。
- 大屏总览包括事件态势、响应建议、T0和T1、任务进度、超时任务、评估成果、工作组成果、地图联动和消息通知。
- 页面必须避免文字重叠、溢出和关键内容遮挡。
- 自动化成果和人工成果在大屏上有明确区分。
- 真实、测试和演练事件使用明显、不可移除的状态标识。
- 人工触发界面支持输入发震时刻、经度、纬度、震级和深度，自动匹配参考位置、行政区、距人民广场距离以及附近断裂。

## 16. 人工触发与破裂方向

- 必填字段为发震时刻、经度、纬度、震级、震源深度和数据来源。
- 可选字段为事件编号、参考地名和正式报编号。
- 默认检索震中周边 50 公里范围内的活动断裂，检索半径可配置。
- 有震源机制解时优先采用机制解确定破裂方向。
- 没有机制解但有邻近断裂时参考断裂走向。
- 两者都没有时生成不设定方向的圆形或椭圆形影响场，并标记“破裂方向待确认”。
- 人工触发与 CENC 正式速报共用同一评估、制图、报告、任务和版本规则。
- 人工触发记录操作人、操作时间、数据来源、触发参数和关联成果。

## 17. AI 知识与问答

- 首期只支持文字提问，回答支持文字、表格和地图联动。
- 空间距离、缓冲区、历史地震、行政区、人口和断层问题由 PostGIS 或专用计算服务完成。
- AI 不自行生成坐标、距离、统计值或空间结论。
- 回答必须显示来源、数据时间和计算口径。
- 没有可靠依据时明确回答“现有资料无法确认”。
- 可以检索预案、规章制度、历史成果、公开论文和授权知识库。
- 可以解释预案条件和已有成果，不替代领导启动响应、发布命令或形成对外结论。
- 外网阶段允许自动联网检索和更新知识库。
- 自动收录仅限可验证的官方来源，非官方材料先进入候选库，经审核后转为正式知识。
- 内网部署阶段关闭联网检索，保留本地知识库和增量更新能力。
- 问答保存问题、检索依据、计算过程、数据版本和操作人。

## 18. 测试与演练

- 系统每天在随机时间自动触发一次测试地震。
- 支持人工触发测试。
- 上海市行政区域内 5.0 至 5.9 级测试事件必须完整生成全部 27 类图件和全部报告。
- 测试成果所有可见文字、文件名和元数据均注明“测试”。
- 演练事件与测试事件独立，演练成果注明“演练”。
- 真实事件优先，测试任务暂停，演练任务按配置暂停或终止。
- 测试事件和成果保留 400 天。
- 演练事件和成果保留 2 年。
- 正式事件长期保留。

## 19. 异常处理与降级

- 数据源中断时自动重试，记录缺口，不伪造事件或结果。
- 单个模型、图层、报告或地图失败时隔离该任务并自动重试。
- 任务失败时通知应急技术组，并在大屏显示。
- 资源不足时优先保证真实事件的烈度、损失、报告和核心图件。
- 通知渠道失败时回落到站内消息。
- 外部联网服务不可用时继续使用本地数据、底图和缓存。
- 所有主机统一校时。
- 持续监控报文接入、任务队列、模型、制图、报告、数据库、对象存储、磁盘和服务器资源。

## 20. 部署、备份与恢复

### 20.1 首期部署

- 首期部署在 Z440 单机外网环境。
- 使用 Docker Compose 运行平台组件。
- 当前机器有两块物理盘：约 1TB 系统盘 `C:` 和约 2TB 高速 SSD 工作盘 `D:`。
- 新增 4TB HDD 作为专用备份盘。
- `C:` 用于操作系统和基础软件。
- `D:` 2TB SSD 用于 PostgreSQL、SeaweedFS、底图缓存、任务运行数据和短期成果。
- 4TB HDD 用于压缩、去重和增量备份。

### 20.2 备份策略

- 每日增量备份保留 30 天。
- 每月完整恢复点保留 12 个月。
- 每月执行一次真实恢复验证。
- 热数据盘设置容量告警。
- 备份盘保留至少 15% 空闲空间。
- 空间不足时停止覆盖旧恢复点并告警。
- 机器或机房整体损坏仍需离线副本，后续可使用移动硬盘定期保存离线备份，首期不依赖 NAS。

## 21. 安全、审计与保留

- 使用本地账号体系。
- 不启用二次验证。
- 高风险操作不进行密码复验，不强制填写原因。
- 分派权限到工作组。
- 组长和代理副组长按名单顺序履职。
- 普通操作保留审计记录。
- 超级管理员可以覆盖错误成果并直接重新发布。
- 超级管理员可以彻底删除原始报文、已发布报告和操作日志。
- 外部接口密钥不进入代码库和设计文档。
- 数据、模型、模板和成果均带版本。

## 22. 首期验收

- 自动速报建立待定事件，正式速报触发评估。
- 手工事件、测试事件和演练事件独立运行。
- 上海市行政区域内一次 5.0 至 5.9 级测试地震，从 `T1` 到全部 27 类图件、4 类核心文档或演示稿和 8 类背景文档生成完成，不超过 5 分钟。
- 自动、正式、修正报文乱序或重复到达时能够去重、合并和生成修订版。
- 升级能够补充任务，降级能够取消未开始任务且保留已有成果。
- 数据源、模型、地图、存储、通知和单任务失败时能够隔离、告警并继续完成其他成果。
- 7 个工作组能够完成任务接收、成果上传、组长或代理副组长确认、版本查看和大屏展示。
- 数据导入、校验、候选版本、发布、回滚、更新提醒和事件快照正常工作。
- AI 问答能够完成断层距离、历史地震、人口、行政区和成果统计问题并联动地图，无依据时不编造。
- 真实事件与测试或演练并发时，真实事件优先。
- 每日随机测试、手工测试、成果保留、超级管理员覆盖和删除规则符合已确认要求。
- 每日增量、每月完整备份和恢复验证正常，不影响正式事件。
- 大屏在 `7680 x 2430` 下无重叠、溢出和关键内容遮挡。
- 所有正式成果不带测试或演练前缀，所有测试和演练成果具有不可移除标识。
